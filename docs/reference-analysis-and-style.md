# 参考小说分析与文风迁移

> 更新日期：2026-08-05
> 状态：五层章节分析与全书文风画像已经实现；真实长篇校准仍待完成。

## 1. 目标

参考分析不是为了生成一份读后感，也不是让模型照着某本书改写。它需要回答三个可核对
的问题：

1. 原文明确发生了什么；
2. 这些内容怎样被组织和讲述；
3. 哪些写作机制可以脱离原作内容，安全地用于新的原创作品。

因此，事实、叙事判断、文风观察和可迁移技法必须分开保存。模型输出不能仅凭“很有
电影感”“像某位作者”这类评价进入写作上下文。

## 2. 分析层

| 层 | 产生方式 | 内容 | 证据要求 |
| --- | --- | --- | --- |
| 结构 | 本地确定性计算 | 字符、段落、句子、句长波动、段长、对话占比 | 可从冻结正文重算 |
| 事实 | 模型 | 人物、场景、事件、伏笔 | 每项精确引用原文字符范围 |
| 叙事 | 模型 | 场景功能、冲突、关系变化、信息释放、节奏、结尾钩子 | 每项精确引用原文字符范围 |
| 文风 | 模型 | 视角、距离、句段节奏、对话、描写、信息流、情绪、用词、修辞、转场、场景出入 | 每项精确引用原文字符范围 |
| 技法 | 模型 | 局部方法、效果、适用和失效条件、执行规则、原创性边界 | 每项精确引用原文字符范围 |

每个模型层都拥有独立状态，可以失败后单独重试。缓存键包含正文哈希、分析 schema、
层、Provider 和模型，因此正文相同且分析契约相同时才会复用。

## 3. 证据契约

模型拿到的是带整章偏移的连续 source segment。每条证据必须包含：

```json
{
  "start": 18,
  "end": 27,
  "quote": "这里必须逐字来自正文"
}
```

服务端接受结果前执行 `source[start:end] == quote`。改写、近似引用、规范化标点或使用
省略号都会失败。证据只证明“这个判断有文本依据”，不自动证明解释是唯一正确的；
作者仍可在章节分析页回到原文核对。

## 4. 文风画像

章节文风层使用固定维度，避免把剧情主题误当成写法：

- 叙事视角与叙事距离；
- 句子节奏与段落节奏；
- 对话组织与描写策略；
- 信息流与情绪传达；
- 用词语域与修辞意象；
- 转场方式与场景进入/退出。

每个章节、每个维度只给出一个有证据的综合判断。证据不足就不输出，不用空洞结论凑满
维度。

全书聚合会为每个维度选择出现最多的标签，同时保留标签变体、覆盖章节和覆盖率。它还
用确定性统计汇总平均句长、句长波动、平均段长和对话占比。覆盖率是观察范围，不是
“作者风格相似度”：两章中的共同信号不能冒充整部长篇的稳定规律。

为了避免原作泄漏，全书画像不携带原文引文，只包含：

- 文风维度和主导标签；
- 出现章节与覆盖率；
- 对机制的解释；
- 可直接执行但不依赖原作内容的规则；
- 明确禁止复用的原作元素。

章节证据仍保存在章节分析中，需要核实时再读取。

## 5. 如何用于写作

### 与来源版本相连的改写或续写

来源作品完成分析后，Agent 工作区会提供：

- `book/analysis/reference/{position}.json`：章节证据化分析；
- `book/analysis/reference/book-profile.json`：全书分析汇总；
- `book/analysis/reference/style-profile.json`：不含原文引文的文风画像。

只有作者明确说“参考这本书的文风/叙述节奏/信息释放方式”时，Agent 才应读取文风画像。
普通续写、讨论和设定修改不能把描述性观察静默升级为创作规则。

### 用于另一部不相关的作品

当前可靠流程是：

1. 在参考书中查看文风画像和对应章节证据；
2. 选择真正需要的局部机制；
3. 将可执行规则保存为技法卡；
4. 由作者改造并绑定到目标作品、章节或场景范围；
5. Writer 只读取已绑定规则与原创性边界。

系统目前不会把一整本参考书画像全局、永久、隐式地绑定到任意原创项目。未来若增加
“参考画像绑定”，它也必须默认关闭、清楚可见、可撤销，并允许逐维度选择。

## 6. 原创性边界

“参考风格”只允许迁移抽象机制，例如：

- 先呈现一个可感后果，后补充来源；
- 在高压对话中缩短叙述句，让动作承担停顿；
- 场景退出时留下一个可在后文核对的问题。

不得迁移：

- 可识别的原句、句群和独特措辞；
- 专有名词、人物关系和世界设定；
- 标志性物件、独特意象或比喻组合；
- 具体情节、揭示答案和场景排列；
- “写得像某位在世作者”这类身份模仿目标。

如果抽象规则无法脱离这些元素成立，它就不是可迁移规则。

## 7. 真实小说验收

用户提供小说后，按以下顺序验收：

1. 在导入预览确认章节边界，不让错误切分污染后续统计；
2. 跑完整分析并记录失败层、重试、缓存命中、tokens 和耗时；
3. 从开头、中段、转折和结尾抽样核对事实与证据；
4. 检查同一文风维度的标签漂移、覆盖率和变体；
5. 选取少量规则生成原创测试章，与未使用画像的结果做盲评；
6. 记录可读性、人物一致性、人工修改量、成本、延迟和任何原作复用问题。

只有任务完成并不代表分析可用。真正的验收标准是：证据准确、画像稳定、规则能改善
原创文本，并且没有把原作内容带进新作品。

## 8. 代码边界

| 模块 | 职责 |
| --- | --- |
| `reference_analysis_schema.py` | 层级 schema、证据验证、章节结果组装 |
| `reference_analysis_metrics.py` | 可重算的文本结构与节奏度量 |
| `reference_analysis_prompts.py` | 每层提示词、依赖层选择和 source segment |
| `reference_analysis_aggregation.py` | 已验证章节的全书事实与文风聚合 |
| `reference_analysis_pipeline.py` | 分层状态机、缓存、重试、租约结果提交 |
| `analysis_repository.py` | 作业、章节层和缓存持久化 |
| `analysis_routes.py` | 分析任务、章节证据、导出和技法保存 HTTP 边界 |

这些职责不能重新合并进 Worker 或 Web 路由。后续新增人物弧、因果链或视角轮换聚合时，
应扩展聚合输入和 schema，而不是添加第二条分析执行链。
